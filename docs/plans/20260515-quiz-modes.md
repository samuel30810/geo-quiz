# 練習模式與隨機模式

## 1. Summary

目前的地圖練習工具只有一種無限循環的隨機出題模式，題目可能重複且沒有結束條件。本次變更新增兩種模式：**練習模式**（題庫全出一次不重複，結束後顯示正確率）和**隨機模式**（隨機抽 20 題不重複，一題 5 分滿分 100，結束後顯示分數）。首頁流程從「直接選地圖」改為「先選模式 → 再選地圖」。兩種模式的作答流程與即時回饋完全一致，差異僅在題數來源與結束畫面。

## 2. Architecture Decisions

本次無架構決策。不引入新技術棧，沿用既有純靜態 HTML + CSS + JS 架構。模式資訊透過現有的 URL 參數機制傳遞（新增 `mode` 參數）。

## 2.5 Artifact Contracts

本次無產出物契約。不涉及檔案產出物或 API 簽名變更。

## 3. Key Assumptions

- 台灣題庫固定 27 題（22 縣市 + 5 離島），世界題庫固定約 50 題（依 `COUNTRY_NAMES` 白名單）。這些數量由資料模組的 `processFeatures` 結果決定，不在 engine 硬寫。
- 隨機模式固定 20 題，兩種地圖皆同。台灣 27 題 > 20，世界約 50 題 > 20，皆滿足抽題需求。
- 沿用既有 RWD 模式（斷點 480px / 768px / 1024px）。
- 不需要持久化成績（重整後重置），與現行行為一致。

## 4. Database Changes

無。純前端靜態專案，無資料庫。

## 5. Backend Changes

無。純前端專案，無後端。

## 6. Frontend Changes

### 6.1 首頁改版 — `index.html`

目前首頁直接顯示兩張地圖卡片（台灣 / 世界）。改為兩步驟選擇流程：

- [ ] **Step 1 — 模式選擇**：顯示兩個模式卡片「練習」與「隨機」。練習卡片的說明文字為「所有題目各出一次」；隨機卡片的說明文字為「隨機 20 題，滿分 100」。
- [ ] **Step 2 — 地圖選擇**：使用者點擊模式後，顯示地圖卡片（台灣 / 世界），沿用現有的 `.mode-card` 樣式。地圖卡片的連結改為 `quiz.html?mode=practice&map=taiwan`（或 `random` / `world`）。
- [ ] **步驟切換方式**：選擇模式後，隱藏模式卡片、顯示地圖卡片，並提供「← 重新選擇」按鈕可返回 Step 1。不換頁，純 DOM 切換。
- [ ] **地圖卡片的題數顯示**：練習模式下，台灣卡片顯示「27 題」、世界卡片顯示實際題庫數量（由 `totalCount` 取得）；隨機模式下，兩張卡片均顯示「20 題」。
- [ ] **地圖卡片的 CTA 文字**：練習模式顯示「開始練習 →」；隨機模式顯示「開始挑戰 →」。
- [ ] **邊界條件**：地圖資料載入失敗時，卡片維持可見但點擊後由 quiz.html 處理錯誤（與現行一致）。

### 6.2 題目引擎改版 — `js/engine.js`

目前 `nextQ()` 每次用 `Math.random()` 從全部 features 隨機抽一個，無去重、無結束條件。改為：

- [ ] **讀取 URL 參數**：新增讀取 `mode` 參數（`practice` 或 `random`），預設為 `practice`。
- [ ] **建立題目池**：
  - 練習模式：將所有 features 複製一份並 shuffle，作為題目佇列。
  - 隨機模式：將所有 features 複製一份並 shuffle，取前 `Math.min(20, features.length)` 個作為題目佇列（防禦未來題庫小於 20 的情況）。
- [ ] **出題邏輯**：`nextQ()` 改為從題目佇列依序取出下一題（shift 或用 index 遞增），取代現行的隨機抽取。
- [ ] **題數顯示**：topbar 的分數區域改為顯示「答對 X / Y（共 Z 題）」格式，其中 Z 為總題數（練習模式 = features.length，隨機模式 = 20）。`QUESTION N` 標籤維持現行遞增邏輯不變。
- [ ] **結束判斷**：當題目佇列用盡時，不再呼叫 `nextQ()`，改為顯示結束畫面。
- [ ] **結束畫面**：
  - 練習模式：顯示正確率，格式為「你答對了 X / Y 題（XX%）」。
  - 隨機模式：顯示分數，格式為「你的分數：XX 分（滿分 100）」。分數 = 答對題數 × 5。
  - 兩種模式皆顯示「再來一次」按鈕（重新 shuffle 題目池、重置分數與 QUESTION N 計數器、維持當前模式與地圖不變）和「返回首頁」按鈕。
- [ ] **「下一題」按鈕行為**：最後一題作答後，按鈕文字從「下一題 →」改為「查看結果」，點擊後顯示結束畫面。
- [ ] **鍵盤快捷鍵**：結束畫面中，Enter 觸發「再來一次」，Escape 觸發「返回首頁」（與現行 Escape 返回首頁一致）。

### 6.3 練習頁面 — `quiz.html`

- [ ] **結束畫面容器**：新增一個隱藏的 `<div id="result-screen">` 區塊，包含結果文字、「再來一次」按鈕、「返回首頁」按鈕。初始 `display: none`，由 engine 在結束時顯示並隱藏 `quiz-main` 的其他內容（地圖、選項等）。

### 6.4 樣式 — `css/style.css`

- [ ] **模式選擇卡片**：新增 `.mode-select-cards` 容器及 `.mode-select-card` 樣式，風格與現有 `.mode-card` 一致（白色卡片、圓角、hover 效果）。不需要地圖預覽圖，改用文字圖示或純文字。
- [ ] **步驟切換動畫**：可選，簡單的 fade 或 slide 過渡效果，使用 CSS transition。
- [ ] **「重新選擇」按鈕**：新增 `.back-to-mode` 樣式，與現有 `.back-btn` 風格一致。
- [ ] **結束畫面**：新增 `.result-screen` 樣式，置中顯示，包含分數/正確率的大字體、按鈕組。
- [ ] **RWD**：沿用既有三段斷點（480px / 768px / 1024px），新增元素在各斷點下的適配規則。
- [ ] **CSS class 衝突檢查**：現有 class 清單中無 `mode-select-*`、`result-screen`、`back-to-mode`、`result-*` 前綴，無衝突風險。

### 6.5 不修改的檔案

- `js/map.js`：地圖渲染邏輯不受影響，不需修改。
- `js/data-taiwan.js`、`js/data-world.js`：資料模組不受影響，不需修改。兩個 config 已有 `totalCount` 屬性可供首頁使用。

### 6.6 邊界條件整理

| 情境 | 處理方式 |
|------|---------|
| URL 無 `mode` 參數 | 預設為 `practice` |
| URL `mode` 值無效（非 practice/random） | 預設為 `practice` |
| 題目佇列用盡時按「下一題」 | 不會發生，最後一題的按鈕改為「查看結果」 |
| 結束畫面按「再來一次」 | 重新 shuffle 題目池、重置分數、回到作答畫面 |
| 地圖載入失敗 | 維持現有錯誤處理，結束畫面不會被觸發 |

## 8. Compatibility Checklist

- [x] 現有 API 的呼叫方是否受影響？— 無 API，不適用。
- [x] 現有 URL 結構是否相容？— `quiz.html?map=taiwan` 仍可運作（`mode` 預設為 `practice`），不破壞既有書籤或外部連結。
- [x] 是否需要 data migration？— 無持久化資料，不適用。

## 9. Out of Scope

- 成績持久化（localStorage 或後端儲存）— 維持重整後重置。
- 錯題回顧功能（結束畫面列出每一題的對錯明細）— 目前只顯示總分/正確率。
- 難度分級或智慧出題（依答錯率調整出題頻率）。
- 計時功能。
- 選項干擾項的智慧選取（依地理相鄰或名稱相似度）。

## 實作偏差記錄

- **偏差 1**：topbar 題數顯示格式
  - 原因：規劃文件 §6.2 要求「答對 X / Y（共 Z 題）」，但設計交接包 `docs/design_handoff_geo_quiz_modes/README.md` §3.1 明確要求改為「第 N / Y 題」格式，以強調進度而非即時分數。實作依設計交接包為準。
  - 影響範圍：`js/engine.js` 的 `updateScoreDisplay()` 和 `quiz.html` 的 topbar 初始 HTML。
